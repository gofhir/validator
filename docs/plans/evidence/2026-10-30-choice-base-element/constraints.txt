ElementDefinition eld-6 | Fixed value may only be specified if there is one type
ElementDefinition eld-7 | Pattern may only be specified if there is one type
ElementDefinition eld-11 | Binding can only be present for coded elements, string, and uri
ElementDefinition eld-13 | Types must be unique by code
ElementDefinition eld-16 | sliceName must be composed of proper tokens separated by "/"
ElementDefinition eld-22 | sliceIsConstraining can only appear if slicename is present
ElementDefinition.contentReference DEF | Identifies an element defined elsewhere in the definition whose content rules should be applied to the current element. ContentReferences bring across all the rules that are in the ElementDefinition for the element, including definitions, cardinality constraints, bindings, invariants etc. | COMMENT | ContentReferences can only be defined in specializations, not constrained types, and they cannot be changed and always reference the non-constrained definition.
ElementDefinition.type eld-4 | Aggregation may only be specified if one of the allowed types for the element is a reference
ElementDefinition.type eld-17 | targetProfile is only allowed if the type is Reference or canonical
ElementDefinition.type DEF | The data type or resource that the value of this element is permitted to be. | COMMENT | The Type of the element can be left blank in a differential constraint, in which case the type is inherited from the resource. Abstract types are not permitted to appear as a type when multiple types are listed.  (I.e. Abstract types cannot be part of a choice).
